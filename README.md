# AI Video Production Skills

把一句创意、参考图、动作视频或首尾帧，规划成可直接交给任意生成与剪辑工具执行的短视频制作包。

> 先用 [`build-ai-video-fast`](./build-ai-video-fast/SKILL.md) 完成 5–30 秒 AI 广告、剧情短片、产品片或社交媒体视频的完整制作规划；需要局部能力时，再调用对应的原子 Skill。

`v0.2.0` 包含 1 个总编排器和 11 个可独立调用的原子 Skill。它不绑定视频模型、不调用付费生成、不承诺已经生成成片；交付的是一份可复用、可验收的 `AI Video Build Pack`。

## 它解决什么问题

AI 视频项目通常不是缺少一个提示词，而是缺少一条能落地的制作路线：素材该怎么分工、先做哪支小样、人物和产品如何跨镜头保持一致、哪些动作必须保留、声音与剪辑何时介入，以及怎样判断结果是否可用。

这套 Skills 适合以下情况：

- 只有一句创意，但想快速拿到一支 5–30 秒短片的脚本、分镜、提示词和剪辑计划。
- 有人物或产品参考图，必须保证身份、外观、场景或风格的一致性。
- 有动作视频，必须保留表演、节奏或运镜，只替换场景或局部内容。
- 已知视频开头、结尾、循环点或变形完成态，不能让关键状态出错。
- 不想被某个模型、价格、积分或按钮路径绑定，希望先获得平台中立的制作方案。

它不是一页“AI 视频万能提示词”。完整项目会被拆成可执行的镜头、素材职责、验收条件和迭代策略。

## 从这里开始：`build-ai-video-fast`

完整视频项目优先使用 [`build-ai-video-fast`](./build-ai-video-fast/SKILL.md)。直接告诉 Codex 你想做什么，或附上现有素材；不需要先填一张复杂表单。

```text
使用 build-ai-video-fast：
为一款便携咖啡机做 15 秒竖屏广告，面向早高峰通勤人群。
卖点是 30 秒出咖啡、可放进背包；希望观众点击购买。
画面干净、有清晨阳光感，中文，无需真人对白。
```

工作流只会补问尚未提供、且会改变路线、时长或验收标准的信息，最多一次五问：

1. 目标：片型、受众，以及希望观众产生的感受或行动。
2. 规格：时长、画幅、发布场景和语言。
3. 内容：主体、必须出现的事件/卖点、台词或 CTA。
4. 素材与约束：文字、图片、视频、音频各自控制什么；哪些元素必须保留。
5. 创作限制：视觉/声音方向、旁白和字幕、迭代次数、交付与授权边界。

非关键缺失项会采用合理默认值，并明确写进制作包的“假设”章节，而不是伪装成已确认事实。

默认建议：社媒、剧情和创作者广告为 **15 秒 / 9:16 / 4 镜头**；产品宣传或功能展示为 **20 秒 / 16:9 / 5 镜头**。通用导出规划为 1080p、30fps、H.264/AAC；本仓库不会实际导出文件。

## 四条制作路线

每个项目只选一条主路线，其余素材进入职责矩阵作为辅助约束，避免把同一个问题拆成互相冲突的并行流程。

| 你最需要控制什么 | 主路线 | 优先结果 |
| --- | --- | --- |
| 没有可用素材，先把创意落成可见画面 | 文字 → 视觉锚点 | 主体、场景、风格与镜头基调 |
| 人物、产品、场景或风格必须一致 | 参考图 → 一致性 | 身份、外观、产品细节与视觉锚点 |
| 动作、表演、节奏或运镜必须保留 | 视频参考/视频编辑 | 动作连续性与镜头语言 |
| 结尾状态、循环点或关键变化不能错 | 首尾帧路线 | 端点锁定与中间过程 |

混合素材按这个顺序决定主路线：**必须保留的动作/运镜 → 必须命中的端点 → 身份/产品一致性 → 纯文字发散**。

## 你会拿到什么

交付物是一个单一 Markdown 文件：[`AI Video Build Pack 模板`](./build-ai-video-fast/assets/AI-Video-Build-Pack-template.md)。它固定包含 11 个章节：

1. 项目目标、已采用假设、风险与授权提醒。
2. 主路线、素材职责矩阵和补充素材建议。
3. 脚本、旁白、时长预算和镜头分配。
4. 分镜表，以及每镜头的视觉锚点、正向提示词和可选负向约束。
5. 保留项、变更项、可观察验收条件与失败恢复方案。
6. 低成本小样、单变量精修、剪辑、转场、BGM、SFX、字幕、导出与最终 QA。

镜头时长必须闭合为总时长；每个镜头都有提示词、验收条件和下一轮只改一个变量的调整方向。

## 使用示例

### 示例 1：一句创意 → 15 秒产品广告

**用户输入**

> 使用 `build-ai-video-fast`：为一款“放进背包也不漏”的随行榨汁杯做 15 秒小红书广告，面向上班族。必须展示通勤、打碎水果、放回包里三个卖点；9:16，中文字幕，无旁白。

**工作流判断**

- 主路线：文字 → 视觉锚点。
- 默认采用 4 镜头，围绕“通勤痛点 → 快速制作 → 防漏证明 → CTA”分配时长。
- 先测试“防漏装包”这一高风险镜头；小样失败时只调整密封结构的视觉锚点或动作，不同时重写风格和分镜。

**交付内容**

一份 15 秒、时长闭合的分镜与提示词包，包含产品细节锚点、单行字幕计划、BGM/SFX 节点、剪辑节拍和发布前检查项。

### 示例 2：人物参考图 → 连续剧情短片

**用户输入**

> 使用 `build-ai-video-fast`：基于这张人物参考图做一支 20 秒雨夜剧情短片。必须保持同一张脸、红色外套和旧相机；结尾是她走进地铁站。9:16，中文短旁白。

**工作流判断**

- 主路线：参考图 → 一致性。
- 参考图负责人物身份、红外套和相机细节；文本负责雨夜氛围和未提供的景别；结尾状态作为辅助端点约束。
- 先制作人物近景和相机细节的小样，再扩展到全镜头，避免在长镜头里才发现身份漂移。

**交付内容**

角色锚点与素材职责矩阵、跨镜头分镜、每镜头的一致性提示词、保留/变更合同、旁白与字幕时间轴，以及人物漂移时的恢复分支。

### 示例 3：动作视频 → 换场景品牌片

**用户输入**

> 使用 `build-ai-video-fast`：保留这段跑步视频中的人物动作、节奏和跟拍运镜，把场景换成未来城市街道，做成 8 秒运动品牌短片。

**工作流判断**

- 主路线：视频参考/视频编辑。
- 视频只负责动作、表演节奏和运镜；未来城市只允许改变环境与灯光，不改人物步频和镜头运动。
- 小样先检验动作保留，再检验城市替换；如果失败，优先收紧“保留项”，而不是无限增加风格形容词。

**交付内容**

视频职责矩阵、保留动作清单、场景变更清单、短镜头提示词、运动音效节点和动作接缝验收标准。

## 小样到成片的执行方式

1. 将 Build Pack 中的关键镜头或短片段交给你选择的生成工具制作低成本小样。
2. 每轮只改一个变量：输入职责、参考锚点、动作/运镜、保留项、端点或节奏。
3. 小样通过验收后，再扩展到全镜头并按镜头预算生成。
4. 按制作包完成剪辑、转场、声音、字幕和发布前 QA。

工作流规划的是制作过程，不会替你购买额度、调用付费接口、上传素材或声称成片已经生成。

## 安装与触发

本仓库没有运行时依赖。将根目录下包含 `SKILL.md` 的 12 个目录安装到 Codex 的 skills 目录后，在**下一轮对话**中即可使用。

- 使用 Codex 安装器时，可直接请求：`安装 linjiahao068-source/ai-video-production-skill 的 v0.2.0 全部 12 个 Skill`。
- 手动安装时，将这 12 个目录复制到 `<CODEX_HOME>/skills/`；Windows 默认位置通常是 `C:\Users\<你的用户名>\.codex\skills\`。
- 完整视频项目以“使用 `build-ai-video-fast`：……”开头；局部问题则直接描述任务，或点名相应原子 Skill。

## 验证与边界

- 11 个原子 Skill：66 条回归用例。
- `build-ai-video-fast`：12 条路由、边界与范围用例。
- 另有 6 条端到端盲测，覆盖产品广告、人物连续性、动作视频换场景、首尾帧循环、旁白/字幕/音乐短片及“单图提示词不启动完整流程”的反例。

验证记录见 [`verified.md`](./verified.md) 和 [`validation/e2e-blind-test-results.md`](./validation/e2e-blind-test-results.md)。

该工作流适用范围是 5–30 秒。少于 5 秒或超过 30 秒时，它会提出压缩、拆分或另行规划建议，而不会静默改写需求。真人、客户素材、商标、受版权保护角色和商业成片仍须由责任方确认授权、隐私、品牌和平台要求；详见 [`NOTICE.md`](./NOTICE.md)。
