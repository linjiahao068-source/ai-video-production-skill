# 快速搭建 AI 视频

交付可直接交给任意生成与剪辑工具执行的单一 Markdown `AI Video Build Pack`。保持平台中立：不调用付费生成，不承诺已生成成片，不写会过期的价格、积分、按钮路径或模型能力断言。

## 先判定边界

只需单点工作时，转交原子 Skill，不创建完整制作包：

- 单张静态图提示词：`image-prompt-specification`。
- 根据一张参考图反推视觉：`reference-image-prompt-reverse-engineering`。
- 已有画面只改一处且必须保留其余内容：`preserve-change-edit-contract`。
- 只比较质量、速度、预算或模型档位：`capability-cost-fit`。
- 只写一个镜头的动作和运镜：`video-direction-specification`。

若目标是 5–30 秒的完整视频项目，或用户要求从创意/素材做到可生成、可剪辑的制作方案，继续本流程。低于 5 秒或高于 30 秒时，不静默改写：说明 v0.2.0 范围，并提出压缩、拆段或另行规划方案。

## 一次完成最小需求采集

先复述已知信息；只在缺失会改变路线、时长或验收时，在**同一轮**补问下列未提供项目，最多五问。能合理默认的非安全信息不阻塞，写入“假设”。

1. **目标**：片型、观众，以及希望对方感到什么或采取什么行动？
2. **规格**：时长、画幅、发布场景和语言？
3. **内容**：主体、必须展示的事件/卖点、台词或 CTA？
4. **素材与约束**：文字、图片、视频、音频各自负责控制什么？哪些元素必须保留？
5. **创作限制**：视觉与声音方向、字幕/旁白、迭代次数、交付限制和授权边界？

采用以下默认值，并在制作包中明示：

- 社媒、剧情或创作者广告：15 秒、9:16、4 镜。
- 产品宣传或功能展示：20 秒、16:9、5 镜。
- 通用交付建议：1080p、30fps、H.264/AAC；只规划，不实际导出。
- 默认无对白；如叙事需要，规划短旁白、单行优先字幕、BGM 与关键 SFX。
- 制作包使用用户语言；仅在外部生成工具兼容性明显受益时，另附英文提示词。

## 选择一条主路线

阅读 [路线与能力组合](references/routing-and-composition.md)，为每个项目选择**唯一主路线**。混合素材按以下优先级选路；其余素材进入职责矩阵，不创建并行主流程：

1. 必须保留的动作、表演、节奏或运镜 → **视频参考/视频编辑**。
2. 必须命中的结尾状态、变形完成态、循环点或关键状态 → **首尾帧路线**。
3. 身份、产品、场景或风格一致性是主要控制来源 → **参考图→一致性**。
4. 没有可用控制素材 → **文字→视觉锚点**。

在制作包中写明：主路线、选择理由、每个素材的唯一职责、未解决风险，以及补素材建议。不要把“多放几张参考”误写为控制策略。

## 组合所需原子 Skill

始终使用 `generation-mode-reference-selection` 定义输入职责，并按交付风险使用 `capability-cost-fit` 规划低成本小样与定向精修。再按主路线加载最少必要的原子能力：

| 主路线 | 必要组合 |
| --- | --- |
| 文字→视觉锚点 | `image-prompt-specification`、`constraint-aware-prompt-expansion` |
| 参考图→一致性 | `reference-image-prompt-reverse-engineering`、`reference-anchor-density`；如有编辑，加入 `preserve-change-edit-contract` |
| 视频参考/视频编辑 | `preserve-change-edit-contract`、`video-direction-specification`、`sequence-continuity-assembly` |
| 首尾帧路线 | `endpoint-anchored-video-synthesis`、`reference-anchor-density` |
| 多镜头和成片装配 | `storyboard-event-budgeting`、`video-direction-specification`；成片加入 `sequence-continuity-assembly` |

不要逐个复述原子 Skill。只把它们的决策写进制作包：职责、镜头预算、视觉锚点、保留/变更合同、端点、连续性和验收条件。

## 制作 Build Pack

复制 [Build Pack 模板](assets/AI-Video-Build-Pack-template.md)，填满其固定 11 章；不删章节。缺失信息以“待确认”或带理由的“假设”标出，不能伪装为事实。

1. 项目摘要与目标。
2. 已采用的假设、风险和授权提醒。
3. 主路线及素材职责矩阵。
4. 脚本、旁白和总时长分配。
5. 分镜表。
6. 每镜头视觉锚点与生成提示词。
7. 保留项、变更项和验收条件。
8. 小样、定向精修和失败恢复策略。
9. 剪辑、转场、BGM、SFX 和字幕计划。
10. 导出规格与发布前检查。
11. 最终 QA 清单。

令所有镜头时长相加等于总时长。每镜至少包含可见动作、镜头/节奏、所需锚点、正向提示词、负向/避免项（若工具支持）、一个可观测验收条件和失败后的**单变量**调整方向。把脚本当作时长预算，不把不可见背景设定塞进镜头。

## 小样、精修与装配

按照 [质量、迭代与权利边界](references/quality-iteration-and-rights.md) 执行：

1. 先用短片段或关键镜头做低成本小样，验证最高风险变量。
2. 每轮只改变一个变量：输入职责、锚点、动作/镜头、保留合同或节奏；保留其余条件和版本编号。
3. 小样通过后，才扩展到全镜头；失败时按制作包中的恢复分支补锚点、简化事件、调整端点或换输入模态。
4. 剪辑前检查动作/空间/节拍接缝，必要时使用空镜、动作匹配或节拍切点；不以随机重复生成掩盖连续性问题。

## 最终检查

输出前逐项核验：时长闭合、素材职责不冲突、每镜有提示词和验收条件、保留项可检查、字幕与旁白可读、声音有时间点、导出规格完整、版权/肖像/商标/客户素材得到相应人工确认。说明该包是制作计划，不是成片、授权意见或平台承诺。

仅抽象复用外部开源项目的方法；第三方代码、素材、模型权重、价格表和大段文本均不并入本 Skill。具体来源和许可证处理见 [质量、迭代与权利边界](references/quality-iteration-and-rights.md)。
